# growth_of_cource_building

Одиниця роботи — **одна пара, яка вміє рости**, не нова лекція з нуля.

Еталон росту: additive material-версії `python_ai_step` (густина не тонша за попередню) і дірки скелета «Потребує допрацювання».  
Антиеталон: material v2 пар 15–16, яка ховала розгорнутий шар.

Шари: [layers.md](references/layers.md). Карта graft: [graft-map.md](references/graft-map.md).

Source deposit: `knowledge_saver/deposits/2026-09-16_growth-of-cource-building/`.

## Коли

Користувач дає пару (або скелет) і просить покращити, розширити, «залишити місце під статті», додати нове джерело, зробити нову версію матеріалів, закрити «Потребує допрацювання» без зламу 80 хв. Не чекай назви скіла.

Немає скелета слотів — спочатку `tactic_of_cource_building`. Немає меню пар — спочатку `strategy_of_cource_building`.

Як писати заповнений факт / схему / тултіп — `explaine_simple`. Як довести вже густу пару до еталону 9/10 — `common_lesson`. Цей скіл вирішує **куди** лягає нове й **що лишається хуком**.

## Ідея

Пара викладається **сьогодні** і приймає матеріал **завтра**.

Нове джерело **graft** в існуючий `id`. Не переписуй сторінку, бо з’явилась одна стаття. Не заліплюй дірку вигаданою енциклопедією «щоб виглядало готово» — тоді справжнє джерело вже нікуди вставити.

Провідні слова: **hook** (місце під майбутнє), **graft** (вживити джерело в слот), **layer** (required / extra / teacher / version).

## Пайплайн

```
1. Snapshot   пара як є: слоти, id, хвилини, джерела, версія
2. Hooks      кожен слот: hole / stub / core / thick
3. Intake     нове джерело (якщо є) → клас і шар
4. Graft      в існуючий id; overflow → extra або нова version-from
5. Leave      решта хуків лишається явною
6. Emit       pair-NN-growth.md + graft.json
```

### 1. Snapshot

Зібрати: `global_index`, title, `duration_min`, material-версія, список `id`+`type`, required хвилини, `sources`, `teacher.md` заголовки, словник.

Цитувати лише ті джерела, які вже в парі або які дав користувач. Дорогий скрейп — спочатку `knowledge-saver`, потім graft з копії.

**Готово:** таблиця слотів без вигаданих блоків.

### 2. Hooks

Кожен слот — один стан:

| Стан | Ознака | Що можна завтра |
|------|--------|-----------------|
| hole | `Потребує допрацювання` або порожньо | заповнити цим типом |
| stub | 1–2 речення, без прикладу / схеми / джерела | потовщити на місці, `id` той самий |
| core | required факт 80 хв, id стабільний | додавати **поруч**, не замість |
| thick | уже густо (як 11–16 / 16–18) | лише extra / teacher / нова версія |

`id` і `type` core-слота — **freeze**. Хвилини required не ріж, щоб впхнути нову статтю. У `theory` freeze також `positions.коротко` (факт 80 хв); `positions.детально` може бути hole/stub, поки немає розбору.

**Готово:** список хуків. Порожній список хуків на тонкій парі — помилка знімка, не «пара вже ідеальна».

### 3. Intake

Нове джерело класифікуй в **один** клас:

| Клас | Куди |
|------|------|
| факт програми | hole/stub `positions.коротко` того ж `theory` |
| розбір / рядок за рядком | `positions.детально` того ж `id`, не новий `theory` |
| приклад / код | sibling `example`/`code` після теорії |
| пастка | `trap` того кластера |
| офіційний практикум / ДЗ | `task` / `homework` |
| глибше, ніж 80 хв | `extra` або deep-study |
| лише викладач | `teacher` одразу після кластера |
| термін | словник + тултіп, не новий theory |

Два класи в одному URL — два graft, не один абзац-мікс.

**Готово:** джерело має клас і шар з [layers.md](references/layers.md).

### 4. Graft

Порядок пошуку слота:

1. hole того самого `type` у тій самій сімʼї понять (`theory` — спочатку порожнє положення: `коротко` для факту, `детально` для розбору)
2. stub того самого факту — потовщити, `id` не міняти
3. sibling після core (приклад до вже існуючої теорії)
4. overflow 80 хв → `extra` кластера або `data-material-version-from` (шар **не тонший** за попередній). `детально` хвилин не додає — це те саме вікно, інше положення.
5. немає місця в схемі → хук `unmatched`, не пʼята зона

Нова material-версія тільки **додає**. Не став `until=N` як єдиний контент пари, якщо `from=N+1` ховає повний шар. Інцидент v2 пар 15–16 не повторювати.

Голос студентських слотів — до читача. Текст джерела не копіюй verbatim у слайд; одне-два речення + посилання в `sources`.

**Готово:** кожне прийняте джерело має `into` (id) і `layer`. Required сума лишилась 80.

### 5. Leave

Після graft покажи, **що ще відкрите**: hole, stub, unmatched. Це і є наступний вхід, коли з’явиться більше матеріалу.

Не видаляй слот, бо «зараз немає тексту». Не зливай два hole в один «загальний блок».

**Готово:** карта хуків після зміни не коротша за потрібне: закриті — в `grafts`, живі — в `hooks`.

### 6. Emit

Два артефакти (схема: [graft-map.md](references/graft-map.md)):

1. `pair-NN-growth.md` — freeze / hooks / grafts / що лишилось
2. `graft.json` — машинний знімок тих самих полів

HTML / `teacher.md` правиш лише якщо користувач просив вживити джерело в живу пару. Тоді graft визначає місце, текст слота пише `explaine_simple` / `common_lesson` / `teacher-materials-skill`.

Зупинись. Не переписуй усю `presentation.html` «заодно».

## Заборонена форма

Не: нова лекція замість graft в існуючі id.  
Не: заліплені дірки вигаданим текстом «на потім перепишемо».  
Не: другий `theory` або `extra «Коротко / детально»` замість `positions.детально` того ж id.  
Не: версія, тонша за попередню повну.  
Не: різати required 80 хв, щоб вліз новий required.  
Не: міняти `id` core-слота.  
Не: джерело лише в прозі, без рядка в `sources`.  
Не: меню пар або порожній скелет замість карти росту.

## Перевірка

- Кожен прийнятий URL має `into` + `layer`.
- Required хвилини = 80 (або ще не розставлені — не вигадуй нову суму).
- Живі hole лишились з текстом `Потребує допрацювання`.
- Кожен `theory` лишає обидва положення; порожнє `детально` = hole, не видалений слот.
- Нова version-from не ховає попередню густину і не ховає `детально` через `until`.
- Немає нового `type` поза схемою `tactic_of_cource_building`.
